# SOAP 진료기록

진료 관리에서 담당 의사가 진료를 시작한 뒤 S(환자 호소), O(진찰·검사 소견),
A(평가), P(계획)를 작성합니다. 접수 시 방문 사유는 별도로 유지합니다.
`방문 사유 가져오기`는 S가 비어 있을 때만 복사하며 작성한 내용을 덮어쓰지 않습니다.

- 각 항목은 최대 20,000자입니다. 빈 항목이 있는 임시 저장도 가능합니다.
- 진료 완료 시 최소 한 항목에 공백이 아닌 내용이 있어야 합니다.
- 완료 후 수정할 수 없습니다. 담당 의사 확인과 version 충돌 검사는 서버에서도 적용합니다.
- 네 항목 중 하나라도 수정하면 저장 전 환자 전환·목록 재조회가 제한됩니다.

저장 API는 `PUT /api/clinic/encounters/{id}/soap`입니다.

```json
{
  "subjective": "환자 호소",
  "objective": "진찰 소견",
  "assessment": "평가 내용",
  "plan": "계획 내용",
  "complete": false,
  "version": 1,
  "diagnoses": [{"code": "A000", "principal": true}]
}
```

조회 응답에도 동일한 네 항목이 포함됩니다. version에는 가장 최근 조회/저장 응답 값을 보냅니다.
기존 `/note` API는 제거했으므로 백엔드와 WPF 클라이언트를 함께 업데이트해야 합니다.

## 기존 DB

백엔드 재시작 시 Hibernate가 SOAP 열 네 개를 추가합니다.
그 후 `SoapSchemaInitializer`가 기존 `encounters.note` 열을 삭제합니다.
요청에 따라 기존 자유 입력 기록은 변환하거나 보존하지 않습니다.
환자, 접수, 방문 사유, 진료 상태와 새 SOAP 내용은 유지합니다.

## 진단명 연결

`GET /api/clinic/diagnoses?query=검색어`로 상병마스터의 완전코드를 검색합니다.
코드(점 생략 가능), 한글명, 영문명, 추가 명칭을 검색하며 최대 50개를 반환합니다.
A 평가 아래에서 진단을 추가·삭제하고 주진단을 지정합니다.
SOAP 저장 요청에 `diagnoses` 배열을 함께 전송하며 빈 배열은 진단 전체 삭제를 의미합니다.
누락된 배열은 거부하여 구버전 클라이언트가 진단을 실수로 지우지 않게 합니다.

진단은 최대 30개, 동일 코드 중복 불가, 주진단은 최대 하나입니다.
진단을 등록한 경우 진료 완료 전에 주진단 하나를 지정해야 합니다.
상병마스터의 주상병사용구분이 N인 코드는 부진단만 가능합니다.
SOAP와 진단은 같은 트랜잭션으로 저장되며 진단만 변경해도 version이 갱신됩니다.
`encounter_diagnoses`에 코드 연결과 저장 당시 진단명·분류 버전을 보관합니다.
검사·처치 오더 발행은 별도 기능입니다.
