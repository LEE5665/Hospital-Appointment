# 약품 목록과 진료별 처방

진료 관리 화면의 P 아래에서 약품명/대표코드/제품코드로 검색합니다.
약품을 선택하고 1회 투여량, 단위, 1일 횟수, 투여 일수, 용법(투여경로·복용 시점)을 입력한 뒤
`목록에 추가 / 수정 반영` → `처방 저장`을 누릅니다. 목록에서 선택하면 수정하거나 삭제할 수 있습니다.
새 처방은 `새 처방 / 입력 초기화`로 시작합니다.

- SOAP와 처방은 별도로 저장합니다. 처방 저장은 작성 중인 SOAP 초안을 유지합니다.
- 처방 초안이 있으면 환자 전환/새로고침/진료 완료 전에 처방 저장이 필요합니다.
- 담당 의사만 진행 중인 진료의 처방을 저장하며 완료한 진료는 조회만 가능합니다.
- 약품당 다른 용법을 표현할 수 있도록 동일 약품의 여러 처방 행을 허용합니다. 최대 50행입니다.
- 투여량은 0.001~99999(소수 3자리), 횟수는 1~24, 일수는 1~365 범위입니다.
  이는 입력 형식 제한이며 약품별 임상 적정 용량을 판단하는 규칙이 아닙니다.

## 저장 구조

- `medications`: CSV에서 추린 대표코드, 상품명, 업체명, 대표행 규격, 전문일반구분, 제품코드, 성분코드 7개 필드.
- `encounter_prescriptions`: 진료와 약품 연결, 저장 당시 상품명·업체명·규격, 투여량·단위·횟수·일수·용법·순서.
- 진료의 `version`을 공유해 SOAP 저장과 처방 저장 간 오래된 요청을 거절합니다.
- `GET /api/clinic/medications?query=검색어`: 최대 50개.
- `PUT /api/clinic/encounters/{id}/prescriptions`: `{ "version": 1, "prescriptions": [...] }`.
  각 항목은 `medicationCode`, `dose`, `unit`, `frequency`, `days`, `instructions`입니다.
  빈 배열은 전체 처방 삭제, 배열 누락은 오류입니다. 진료 조회 응답의 `prescriptions`로 조회합니다.

이번 기능은 처방 내역 등록·조회입니다. 처방전 출력/전송, 보험 청구, DUR 연동은 포함하지 않습니다.

## 최초 약품 적재

`MedicationDataInitializer`가 서버 시작 시 `medications`가 비어 있을 때만 CSV를 적재합니다.
전체 적재는 한 트랜잭션이고 500개씩 배치 저장합니다. 오류 시 일부만 남기지 않고 시작을 실패시킵니다.
파일을 교체해도 기존 목록을 자동 덮어쓰지 않습니다. 최초 동시 기동은 한 인스턴스에서 진행합니다.

```properties
clinic.medication.init.enabled=true
clinic.medication.init.resource=classpath:data/의약품표준코드.csv
clinic.medication.init.charset=MS949
```

제공된 파일은 CP949입니다. UTF-8 파일로 바꾸면 charset도 UTF-8로 변경합니다.
CSV 따옴표 안 쉼표·줄바꿈·이스케이프 따옴표와 BOM을 처리합니다.

- 취소일자가 없는 `전문의약품`, `일반의약품`, `전문,희귀`만 사용합니다.
- 한약재, 원료의약품, 의약외품, 구분 없는 행은 현재 목록 범위에서 제외합니다.
- 대표코드를 키로 포장별 중복을 합칩니다. 표준코드=대표코드인 행을 우선하고 없으면 첫 유효 행을 사용합니다.
- 규격은 대표행 값만 사용하고 `없음`은 빈 값으로 저장합니다. 포장행의 용량을 처방 투여량으로 추정하지 않습니다.
- 포장형태·수량, 개별 포장 표준코드, 허가일자, 비고, ATC, 일련번호 등 나머지 열은 저장하지 않습니다.
- 취소일자가 비어 있다는 조건은 현재 급여/유통 여부를 보증하지 않습니다. 이 파일은 누적 코드 매핑 자료입니다.
